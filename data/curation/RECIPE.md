## Why a derived dataset at all

`raw/` is the evidence of what was downloaded and is never modified. `curated/` is what the experiments actually read. Separating the two means every transformation applied to the imagery is an explicit, reviewable decision rather than an accident of extraction, and the derived set can be rebuilt bit-identically from `raw/` plus this recipe.

## Governing rules

**rgb downscale** — The locked training input is 640 px (ADR-001). FLAME 3 ships 8000x6000 visible frames at ~20 MB each; decoding those per sample makes the dataloader, not the GPU, the bottleneck. Capping the long side at 1280 keeps 2x headroom for the +/-0.3 scale augmentation and the SSL random-resized crop while cutting the RGB payload by more than an order of magnitude. Bounding boxes are unaffected because D-Fire stores them in normalised YOLO coordinates.

**thermal never resampled** — Resampling or lossily re-encoding a radiometric raster destroys the measurement that makes the thermal source scientifically interesting. Thermal frames keep their original grid and are written as lossless float32.

**thermal to celsius** — Storing Celsius makes the curated dataset self-describing and lets thermal normalisation use physically motivated limits instead of blind percentiles (manuscript section 3.6.2). The conversion is an exactly invertible affine map.

**one representation per frame** — FLAME 3 provides each thermal frame as raw counts, an orthorectified Celsius product, a rendered colour map, and a FLIR container. Only the raw counts are ingested: the colour map carries no radiometric information, the orthorectified product is a resampled derivative, and ingesting several would multiply the source and mix incompatible semantics.

**allow list** — Inclusion is an allow-list of directory globs rather than a deny-list, so a subdirectory added by a future dataset release cannot be ingested without a deliberate recipe change.

## Traceability

`provenance.csv` holds one row per derived file: its path, the raw path it came from, the SHA-256 of those raw bytes, and the operation applied. Any curated file can therefore be traced to the exact input it was produced from, and the recipe hash above pins how.

## Rebuilding

```bash
python scripts/prepare_datasets.py        # stage 1: verbatim extraction -> raw/
python scripts/build_curated_dataset.py   # stage 2: this recipe        -> curated/
```

A different recipe version means a different derived dataset. Runs record the recipe hash, so a result can always be matched to the data it was computed on.
